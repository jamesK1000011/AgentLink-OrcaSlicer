# OrcaSlicer, headless

## The loop
1. `orca_project { action: new, files, path }` makes the project from model files (STL, OBJ, 3MF, STEP …), with presets if given (`bundle`, or `machine`, `process`, `filament` names — the person's own presets too: what they inherit is merged in and empty lists are dropped, so the command line takes them), minimal ones otherwise. The bed type is chosen so every filament goes on it (its bed temperature there is above 0): `bed_type` if given and it fits, else the printer's default, else Textured PEI, High Temp, Engineering, Cool, Textured Cool, Supertack. The answer gives `bedType` and `bedTypes` (all that fit): ask the person which plate is on the printer when it matters, and set `curr_bed_type` to change it. Inside Agent Link for FreeCAD, `bodies` makes it from FreeCAD bodies with their print setup's presets. Each object then names its `body` (in `new` and `info`), matched by the file it was loaded from, never by order or by a name's start.
2. Change it at any level with `orca_project set { scope project|object|part|range|plate, key, value | settings }` — every value is checked against OrcaSlicer's own table (`action: settings { query }` lists keys, types, limits, values). `slot` sets one filament's value.
3. `orca_paint { object, kind supports|seam|fuzzy_skin|color, state, where }` paints the triangles where says: `normal [x, y, z]` (within degrees), `box`, `below` / `above` a height, in object coordinates. With FreeCAD, `faces` paints by face names. `kind texture` adds a Texture Displacement layer instead: `texture { image (PNG) | library, depth, tileSize, rotation, projection, blend, … }` on the triangles where says; `texture { slot }` edits a layer, `{ slot, remove }` removes it. `orca_slice` bakes the relief into the part as it slices (OrcaSlicer's `--bake-texture-displacement`, the same bake as the panel's Bake button); a colour layer gives relief only, not colour.
4. `orca_slice { path }` slices it; `gcode_read` shows layers, moves and views.
5. The return leg: the model changed, then `orca_project replace { object, file }` (or `body`) — its settings, modifiers and place stay; paint goes and is painted again.
6. `orca_project strength { object }` reads walls, infill and layers against the part's size (a feasibility estimate); with FreeCAD, `fea_setup { printed: { project, object } }` takes them into the strength study.

## orca_project actions
- Objects: object_add { body | file (STL, OBJ, 3MF, STEP, a ZIP) | handy | primitive cube|cylinder|sphere|cone|disc|torus + size, plate, at }, object_remove, copy, instance { count, move | remove, instance }, instance_to_object, printable, place { move, rotate, scale, at [x,y], drop }, lay_flat { face | normal }, scale_to_fit, fill_bed { spacing }, grid { nx, ny }.
- Parts: part_add { kind modifier_part|negative_part|support_blocker|support_enforcer|normal_part, file | box [x,y,z] + at | primitive + size + at | body, name, settings }, part_remove, replace { body | file }, emboss { text | svg, size, depth, at, rotate, kind } (FreeCAD draws the letters).
- Mesh: mesh { op simplify (FreeCAD)|fix|smooth|subdivide|mirror|boolean (with, mode; FreeCAD)|cut (axis, at, keep)|cut_grid (size)|split|split_objects|merge (objects)|decompose_color }.
- Layers: layer_heights { profile [[z, h]…] | adaptive 0..1 }, gcode { z, kind pause|color_change|tool_change|template|custom, gcode, extruder, plate, remove }, brim_ears { points, radius }.
- Filaments and presets: filament { slot | like, color, type, settings | remove }, flush { matrix, multiplier }, presets { machine, process, filament | bundle }.
- Plates: plate { object, plate } (moves it; the next number makes a plate), plate_add, plate_remove, plate_duplicate, plate_move { plate, to }, set { scope: plate, key: name|locked|bed_type|print_sequence … }. A plate's bed_type is written as OrcaSlicer saves it (the plate's own bed_type) and as the project's curr_bed_type, which the command line slices with; the other plates are given their own first so they keep theirs. It is read back from the saved file; if it did not take, set answers with an error, never a success. bed_type "" takes the plate's own away.
- Bed type and filaments: each filament has a bed temperature per bed type (cool_plate_temp, eng_plate_temp, hot_plate_temp, textured_plate_temp, textured_cool_plate_temp, supertack_plate_temp); 0 means it does not go on that plate and the slice stops ("Cool Plate does not support filament 1"). orca_slice then names the bed types that would work.
- OrcaSlicer's own: arrange, orient (options allow_rotations, align_to_y_axis …), cli { options } (uptodate, repair, clone_objects, repetitions, scale, rotate, ground_face_normal …). arrange works on one plate at a time: each object stays on its plate. A locked plate is not arranged. An object that does not fit goes to a new plate, and `overflow` names it.
- info { object } (with its effective print settings), saveAs writes a copy.

## Numbering, limits and time
- Paths: a relative path is in the output folder (`orca_status` names it). Outputs of a slice or an export go in `<project>-out/`, the sliced project is `<project>-sliced.3mf`.
- Objects are named or numbered from 1 as `info` lists them (a part of the name matches too: the first hit wins); parts from 1; instances from 0; plates from 1; filament slots from 1; texture layers (slots) from 0; G-code layers from 1 as OrcaSlicer numbers them (layer 1 is the first, the last is the layer count), G-code moves from 0.
- Lengths are mm and angles degrees. `where`, `box`, `at` for a part and `cut at` are in the object's own coordinates (`info` gives `size`); `place at` is [x, y] on the object's own plate; `info`'s `placed` is in the project's world, where plates stand side by side.
- Limits: instance `count` 1 to 200, `grid` 1 to 50 each way, `fill_bed` 200 copies, `cut_grid` 400 pieces, `smooth` 1 to 50 iterations, 8 texture layers, `orca_slice` svg `layerHeight` 0.01 to 10 mm.
- The tools work on the project file. A project that is open in OrcaSlicer's window is not updated: the person reloads it, and a save from the window afterwards overwrites the change.
- Time: reading and changing a small project takes milliseconds; every call reads and writes the whole project, so large meshes cost more on each call (not measured). `new`, `arrange`, `orient`, `cli` and the exports that run OrcaSlicer are allowed 10 minutes, a slice 15; the server answers no other call meanwhile. When the client gives up on a long slice, the slice still finishes: `gcode_read { path: "<project>-sliced.3mf" }` reads it.
- A refused value changes nothing: the project is saved only after every value of the call has been checked.

## Traps
- OrcaSlicer's own window open: when its command line cannot run beside it (or another copy holds its lock), the calls that run OrcaSlicer (new, arrange, orient, cli, orca_slice, orca_calibrate) answer `busy`, say so, and change nothing. `orca_status` gives `windowOpen`. Ask the person to close the window when they are done there; never close it for them.
- Plates sit side by side in the project's world (a bed and a fifth apart): `place at` is on the object's own plate.
- Calibrations (`orca_calibrate`) use the models of the OrcaSlicer on this computer; the retraction tower rewrites the sliced G-code, so slice it with `orca_slice`.
- Starting a print is the person's call.
